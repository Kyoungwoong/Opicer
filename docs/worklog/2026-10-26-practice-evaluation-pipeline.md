## 분석 (구현 전 상태)
- **벡터**
  - `good_answer_sample.embedding vector(1536)` 하나뿐이다(OpenAI text-embedding-3-small, 단위 벡터).
  - 검색은 `order by embedding <-> :q limit 3`, 즉 정확 L2 검색이다. 인덱스, 하한선, 다양성 처리가 없고 NULL도 포함된다.
  - level/tag 하드 필터는 데이터가 없어서 사실상 동작하지 않았다(업로드 level은 항상 AL).
  - **임베딩 저장 자체가 실패하는 버그**가 있었다(bytea 바인딩).
- **평가**
  - 요약 화면의 "분석/수정" 버튼을 수동으로 누르는 방식이고, 결과는 Claude 자유 텍스트다(모델 하드코딩, 프롬프트에 "IL~IM" 고정).
  - **세션 리포트, 예상 레벨, 역량 기준이 없었다.** `/analyze`, `/improve`는 과금이나 호출 제한이 없었다.
- UserSpeechProfile은 문서에만 있었다.

## 결정 / 계획
- 정립한 프로세스:
  ```
  [준비] 목표 레벨 선택 → [녹음] 질문별 녹음 → [제출] 전사 + 세션 저장 + 평가 작업 등록
    → [백그라운드] 답변마다 수치 신호 → 참고 샘플 검색 → LLM 구조화 평가(역량 루브릭) → 검증·저장
    → [집계] 리포트(예상 레벨·범위·신뢰도, 역량별 레벨, 반복 문제 Top3, 팁)를 코드로 계산
    → [화면] 템플릿 리포트 + 답변별 교정/개선 스크립트
  ```
- "답안"은 **코드로 정의한 역량 루브릭**(과제 수행, 담화 구성, 문법·시제, 어휘·표현)이다. 참고 샘플은 가이드다.
- **유사도 알고리즘**(ADR 0001)
  - 코사인 `<=>`, topic 범위 정확 KNN
  - 후보 12개 → 하한선 0.25 → MMR(λ=0.7, k=3)
  - HNSW 전환 조건: 주제당 5~10k건 또는 p95 50ms 초과
- **리포트 템플릿화(토큰 절감)**: LLM은 짧은 구조화 JSON만 출력하고, 리포트 수치와 문장은 코드와 템플릿이 채운다.
- **PR 분할**
  1. rag
  2. evaluation 도메인
  3. 모델·계약(ai_job)
  4. 평가기
  5. 워커
  6. web 연습
  7. web 기록
  8. 정리
  - 추가 요청은 다음에 반영한다.
    - **STT 목 모드**(PR-2 다음 작은 PR)
    - **추천 표현**(PR-4 keyExpressions)
    - **관리자 마크다운 평가 가이드**(PR-4 다음)
    - **내보내기용 HTML 리포트 템플릿**(PR-6/7)
- **데이터 확장(다음 단계 설계)**: 모델 학습(fine-tuning)은 하지 않는다. 대신 참고 자료 창고를 키운다.
  - ① 관리자 일괄 업로드
  - ② AI 생성 예시를 검수 후 등록
  - ③ 동의한 사용자 고평가 답변을 비식별화하고 승인 후 승격
  - ④ 동영상 크롤링은 하지 않는다(약관·저작권)
  - 공통: 출처, 레벨, 검수 상태를 기록하고, 코사인 0.95 이상이면 중복으로 막는다.
